# mrwin Rust backend

Compiled implementation of the exact sub-quadratic right-censored hierarchical
win/loss algorithm (`inst/spec/fast-hierarchical-win-algorithm.md`). It is an
**optional** performance backend: the package builds, checks, and runs fully
without it using the `dense` and `sparse` R backends. When a Rust toolchain is
present at install time, `backend = "rust"` becomes available.

## Layout

```
src/
  Makevars        (generated by ./configure; not committed)
  Makevars.win    (generated by ./configure.win; not committed)
  entrypoint.c    forwards R_init to the extendr module (guarded by MRWIN_HAVE_RUST)
  rust/
    mrwinkernel/  pure-Rust core: the algorithm. No external deps, fully tested.
      src/lib.rs        dominance engine (Fenwick + value-pivot CDQ) + unit tests
      tests/parity.rs   cross-language parity vs the Python reference
      tests/parity_fixtures.txt
    mrwinrust/    extendr bindings exposing the core to R (needs libR to build)
      src/lib.rs
configure        detects cargo, generates src/Makevars
configure.win    same, for Windows (src/Makevars.win)
R/
  backend_rust.R       backend = "rust" wiring (availability-guarded)
  extendr-wrappers.R   native interface (regenerate with rextendr if signatures change)
```

## What is verified without R

The **core crate is fully tested with no R and no network**:

```bash
cd src/rust/mrwinkernel
cargo test            # unit tests (fast vs brute, all K) + Python parity
```

The tests prove the Rust core reproduces the dense kernel exactly: bit-exact for
unweighted counts and within 1e-9 for weighted totals, for K = 1..4, including
heavy ties and right-censoring. The Python parity fixture is regenerated with:

```bash
PYTHONPATH=python python3 -m p1_engine_v5.gen_parity_fixtures \
    src/rust/mrwinkernel/tests/parity_fixtures.txt
```

## Building the R backend (requires Rust + R)

The R-package linkage is wired and standard. With a Rust toolchain installed
(https://rustup.rs):

```bash
R CMD INSTALL .        # ./configure finds cargo and builds + links mrwinrust
```

`./configure` generates `src/Makevars` that runs
`cargo build --lib --release --manifest-path=./rust/mrwinrust/Cargo.toml`
and links the resulting static library; `src/entrypoint.c` (compiled with
`-DMRWIN_HAVE_RUST`) forwards routine registration to extendr's
`R_init_mrwinrust_extendr`. If cargo is not found, `./configure` produces a
Makevars with no Rust, the package installs with dense/sparse only, and
`mrwin:::.mrwin_rust_available()` returns `FALSE`.

If you change the Rust function signatures, regenerate the R bindings with
`rextendr::register_extendr()` and re-document.

### Verify

```r
mrwin:::.mrwin_rust_available()      # TRUE when the compiled backend is present
testthat::test_file("tests/testthat/test-backend-rust.R")   # parity vs sparse @ 1e-10
```

The testthat file is skipped automatically when the compiled library is absent.

## Notes

- Building `mrwinrust` fetches `extendr-api` from crates.io (network at build
  time). For an offline/CRAN build, vendor the crates with `cargo vendor` and add
  a `src/rust/.cargo/config.toml`.
- The `mrwinkernel` crate has no dependencies and never needs network.
